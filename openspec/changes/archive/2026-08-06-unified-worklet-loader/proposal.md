## Why

AudioWorklets are currently loaded using `blob:` URLs generated by `vite-worklet-isolator.ts`. In environments with strict Content Security Policies (e.g., `worker-src 'self'`) or constrained iframe sandboxes, the browser blocks `blob:` URLs, causing worklet initialization to fail. We need a unified fallback strategy that gracefully degrades to `data:` URIs or other acceptable methods to guarantee worklet loading without requiring the consumer to manage static assets or modify their CSP.

## What Changes

- Modify `vite-worklet-isolator.ts` to export the transpiled raw JavaScript string instead of a generated `blob:` URL.
- Introduce a new `WorkletLoader` utility in the Infrastructure layer that takes the raw code string and progressively attempts to load it via `URL.createObjectURL(blob)`, falling back to a Base64 `data:` URI if the former fails.
- **BREAKING**: Refactor all existing engine plugins (e.g., `SidechainDucker`, `FiltersPlugin`) to use the new `WorkletLoader` rather than directly passing an imported URL to `audioContext.audioWorklet.addModule()`.
- Export the `WorkletLoader` in the engine's public API so external packages (like `@scene-grid/inspector`) can receive it via Dependency Injection (DI) to load their own worklets, maintaining strict package isolation.

## Capabilities

### New Capabilities
- `unified-worklet-loader`: A fallback-aware worklet loading mechanism that ensures `AudioWorkletProcessor` scripts can be loaded in CSP-constrained and sandboxed environments.

### Modified Capabilities

## Impact

- **Infrastructure Layer**: Introduces `WorkletLoader.ts`. Modifies `vite-worklet-isolator.ts`. Updates plugin implementations to use the new loader.
- **Dependency Rule**: This change is purely within the Infrastructure layer and build tooling. The Domain layer remains absolutely isolated with zero side-effects and no outward dependencies, strictly adhering to the architectural rules.
